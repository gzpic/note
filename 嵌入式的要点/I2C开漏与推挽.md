# I²C：开漏与推挽

## 1. 推挽输出（Push-Pull）

推挽输出内部可以粗略理解为上下两个 MOS 管：

```text
        VCC
         │
      [上MOS]
         │
GPIO ────●
         │
      [下MOS]
         │
        GND
```

- 输出 1：上 MOS 导通、下 MOS 关闭，GPIO 被主动拉到 VCC。
- 输出 0：上 MOS 关闭、下 MOS 导通，GPIO 被主动拉到 GND。
- 因此推挽既能主动拉高，也能主动拉低。
- 优点是驱动能力强、上升下降速度快，通常不需要外部上拉电阻。
- 常见于普通 GPIO 输出、SPI、UART TX 等。

## 2. 开漏输出（Open-Drain）

开漏可以粗略理解为只保留下方用于拉低的 MOS 管：

```text
       VCC
        │
      上拉电阻
        │
GPIO ───●
        │
      [MOS]
        │
       GND
```

开漏只有两个真正的电气状态：

1. MOS 导通：主动把线路拉到 GND，得到 0。
2. MOS 关闭：释放线路，进入高阻态。

因此：

> 开漏所谓的“输出 1”，并不是 MCU 主动输出高电平，而是 MCU 放开线路，由外部上拉电阻把线路拉高。

可以简单记成：

- **推挽：1 我拉高，0 我拉低。**
- **开漏：0 我拉低，1 我撒手。**

## 3. 为什么 I²C 使用开漏？

I²C 的 SDA、SCL 是共享总线，可能有多个设备连接在同一根线上。

如果使用推挽，一个设备主动输出高电平，而另一个设备主动输出低电平：

```text
VCC → 设备A上MOS → SDA → 设备B下MOS → GND
```

两个输出端会“硬顶”，形成很大的冲突电流，可能损坏 IO。

使用开漏以后，所有设备都只能：

- 拉低线路；
- 或者释放线路。

没有任何设备直接主动把线路连接到 VCC，因此多个设备共享线路时不会出现推挽式的高低电平硬冲突。

## 4. 为什么一个设备为 0、另一个设备为“1”不会短路？

假设设备 A “输出 1”，设备 B 输出 0。

实际上：

- A：关闭自己的 MOS，释放线路；
- B：打开 MOS，把线路拉到 GND。

真实电流路径为：

```text
VCC
 │
上拉电阻
 │
SDA
 │
设备B MOS
 │
GND
```

所以这里确实存在电流，但它经过了上拉电阻，不是 VCC 与 GND 的直接短路。

例如：

- VCC = 3.3 V
- 上拉电阻 = 4.7 kΩ

则低电平时电流约为：

```text
I = 3.3 V / 4.7 kΩ ≈ 0.7 mA
```

因此关键有两点：

1. 开漏的“1”只是释放线路，并没有主动连接 VCC。
2. 总线的高电平由上拉电阻提供；有人拉低时，上拉电阻同时起限流作用。

## 5. 线与（Wired-AND）

由于任何设备拉低都会使总线变为低电平：

| 设备 A | 设备 B | SDA |
|---|---|---|
| 释放 | 释放 | 1 |
| 拉低 | 释放 | 0 |
| 释放 | 拉低 | 0 |
| 拉低 | 拉低 | 0 |

因此可以理解为：

> **低电平优先：只要有一个设备拉低，总线就是 0；只有所有设备都释放，总线才是 1。**

这就是 I²C “线与”的电气基础。

## 6. 与 I²C 协议机制的关系

开漏 + 上拉不仅是为了防止电气冲突，还直接支撑了 I²C 的多个机制：

- **ACK/NACK**：主机释放 SDA，从机通过拉低 SDA 返回 ACK。
- **多主仲裁**：主机发送“1”时实际是释放 SDA，如果读回 0，就知道其他主机正在拉低，从而发现自己仲裁失败。
- **时钟拉伸**：从机可以主动把 SCL 拉低，阻止 SCL 被上拉为高电平，让主机等待。
- **多设备共享总线**：多个设备都遵守“只拉低或释放”，避免输出端硬冲突。

## 7. 面试短答

> 推挽输出可以主动拉高和主动拉低，速度快、驱动能力强，但多个输出端输出相反电平时会产生冲突电流。开漏只能主动拉低，高电平靠外部上拉电阻产生。I²C 使用开漏，使多个设备可以安全共享 SDA 和 SCL，并形成“低电平优先”的线与特性，从而实现 ACK、多主仲裁和时钟拉伸等机制。
